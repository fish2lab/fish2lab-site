十月十一日下午一点二十，我把一份哈工大一校区的教室数据交给 Claude Opus 5.5，想要一张能搜教室、能带人走到门口的校园地图。下午三点零八分，仓库里有了一个等轴测的 Three.js 地图，十栋楼的室内平面，跨楼层的寻路，部署好的网页，一套录屏脚本，以及一条九十秒的 4K 宣传片。中间一百零八分钟，三个 worktree 里的 agent 轮流干活，主会话负责合并。总开销大概是70美元。

付出70美元，我拿到的是一个什么都有的文件夹，里面有：产品、测试、录制工具、成片、部署开关，全是文本，全能重放。回头看这三周，北交东方project摊位的 4K 循环短片、六集纯代码做出画面的科普视频、以及颇具开源精神的，科普视频模板，其实都是这个形状。

终于，Agent的能力跨过了一条线，从“前端已死”，到现在内容的单位，已经从「一个AE工程 or PR项目」变成了「几万行代码，能重新生成作品的仓库」。笔者会通过这篇文章，把这件事从头讲一遍，对象是开发者、vibe coder，也包括做数字媒体的从业者。

## 生成式视频给你结果，代码视频给你源码

做帕秋莉讲座之前，我先想清楚了一件事：agent 看不了视频。它能看的是一张张截图，是离散的采样。所以一部要让 agent 来做的片子，必须能被任意采样，问它第 1453 帧长什么样，它就能当场画出来，和前后发生过什么无关。于是模板的第一条规矩是，画面等于 f(t)。每一帧只由当前时间决定，不存状态，不用随机数，要抖动就用带种子的哈希。模板自带的第一页动画讲的就是这件事：帕秋莉在书页上写下公式，琪露诺问「那直接录屏不行吗」，帕秋莉说录屏一卡就掉帧，我们把时钟拨到第几帧，截一张图，再拨下一帧。

这条规矩定下之后，视频的性质变了，它从一段录下来的东西，变成了一个可以编译的程序。程序员熟悉的那套工具突然全都能用在视频上。想出片，把全片切成四段交给四个无头浏览器，拼起来和顺序渲染逐像素一致，九十七秒的片子在 MacBook Air 上五十六秒出完。改了第三段，只重渲第三段，其余无损拼接；改了所有段共用的画具文件，就得手动让依赖它的段失效。这就是 make，只不过目标文件是 mp4。视频可以 git diff，可以回滚，可以开分支让两个 agent 各画一版。

这也是我坚持不用 AI 生图、生视频的原因。生成式视频给你的是从分布里抽出来的一个样本，你想让魔理沙的帽子往上挪二十四个像素，它只能重新抽一次，帽子以外的东西也一起变了。代码视频给你的是源码，帽子是一个数，改了它，别的什么都不动。对数字媒体的从业者来说，这大概是 Opus 5.5 之后最值得重新估量的一件事：可编辑性。以前要拿到可编辑性，得付出一整套 AE 工程和熟练的手；现在它变成了代码的天然属性，而代码恰好是 agent 最擅长写的东西。

## 审美要编译成数字

touhou 模板的十四个角色站在一起，头和身子的大小分毫不差。做到这一点，靠的不是 agent 的眼睛，而是一份部件表：脖子关节在哪，脸最宽处多宽，眼睛中心的坐标，裙摆下缘的高度，所有角色照抄同一组数，只有帽子、耳朵、蝴蝶结各有各的高度。

模板的经验文档里记着一句我后来反复想起的话：agent 按数值规格写的时候很稳，让它自己「看图改图」，就会越改越偏。我的理解是，看图改图是一个没有不动点的循环，每一轮 agent 都在修正上一轮自己引入的偏差，审美没有锚，只能漂移。按数值写就不一样了，数是锚，偏了可以对回去。这和我在 [🐟NN](/blog/fish-neural-network) 里写过的视角是同一个结构：agent 是可以调参的网络，人是损失函数。魔理沙在十月八日下午加入合照，接下来七十分钟里有六个提交，帽子前后返修三次，最后一次是整体上移二十四个单位，头发一次，眉毛一次。每一个提交都是一次梯度更新，梯度由人给出，更新落在部件表的某个数上。返修的结论再写回规格，比如「帽子要罩住头顶，不许有头发从两层纸之间露出来」，下一个角色就不会再犯。人的审美就这样一点点被编译成了数字。

另一种编译方式是约束。北交摊位的 4K 屏可能没有网络，片子必须双击 HTML 就能放，不能用模块，不能走 CDN，图片要嵌进文件。连转台上旋转的键山雏玩偶，都没法引入 Three.js，只能让 agent 写一个很小的软件渲染器，最近邻贴图，低饱和，外面描一圈墨线。这些限制最后长成了这部片子的画风：木刻的墨块，刮痕的白线，每秒抖八次的手写楷体，七段互不相干的画像《图画展览会》一样靠转场串起来。当 agent 什么都能写，「写什么」反而失去了区分度，**约束成了作者的签名**。

## 选一种自带诚实的视觉语法

hit-map 有一个绕不开的事实：十栋楼的室内平面，没有一栋是实测的。它们是从教室编号的规律、官方地图上的面积和卫星图的屋顶形状推出来的。一个画得像照片的 3D 校园，会让这些推测看起来像真的。

所以我选了图纸。工程图纸这个体裁本身就允许「示意」，它的读者天然知道图纸是抽象。在这个前提下，图纸的每个元素都是一句陈述：相机是正交的，缩放被定义成「每米多少像素」，右下角图名栏里的比例尺是相机参数算出来的真比例；线是发丝宽度，面是平涂，色板网页和 WebGL 共用一份；夜里地图变成晒图蓝图，变的时刻由哈尔滨每个月的日出日落决定。数据结构里每栋楼标着可信度，界面上非实测的楼带一枚「示意布局」的徽标，图名栏里写着「数据：示意布局」。这个徽标放在图纸里一点也不违和，因为图纸本来就有标注的地方。选对体裁，诚实就不需要额外的设计。

这个项目里还有一个变化让我很在意：每个产品决策都有了出处。开工前，调查 agent 用几分钟读了一堆导航研究，其中一条说只在需要做决定的路口给指令，和连续播报一样有效；另一条说三维地图缩短的是出发前的定向时间，跨楼层的判断反而是二维更准。于是指令只在决策点出现，直走合并，换层只说一次；总览用等轴测，换层用「一摞楼层」的拉开视图。冬天默认「少出门」，室外路段代价乘三，暖廊自然被选中，这是哈尔滨的常识。以前这样的调研要一个 PM 花一周，现在它是开工前的一个步骤。调研的成本趋近于零之后，「拍脑袋」就成了一种主动的选择。

## 可分享即可拍摄：类 Devin 宣传片

Devin 那类宣传片让人记住，原因在于它把 agent 的工作过程本身当成了内容，观众看着一句话变成一个东西。版式上也有很强的辨识度：暖灰底，黑色胶囊按钮，带红黄绿三点的大窗口，边缘压着悬浮的放大卡片，背景是缓慢漂移的档案拼贴。hit-map 的宣传片借了这套语法，但把每个元素都换成了产品自己的东西：拼贴的图块是各楼的平面图和录屏局部，前层清晰、快，后层虚化、慢；右上角是一块图名栏，写着 HIT-MAP、场景名和 01 / 12，是图纸的标题栏搬进了片子。

真正让这条片子能在一个下午做完的，是排在版式前面的两件事。

第一件，产品可以被导演。hit-map 从第一天起就用网址表达全部状态，因为它要印成教室门口的二维码，扫码即出路线。网址里带起点、终点、模式，甚至可以伪造时间，把地图拨到晚上七点半。录片的时候，这些参数就是分镜：打开一个网址，就到了想拍的状态，不需要谁去点鼠标。我后来意识到，**可分享和可拍摄是同一个性质**，一个产品的任何状态如果都能用一串字符重现，它就既能被转发，也能被导演，还能被测试。

第二件，时间可以被虚拟化。屏幕录像是实时的，4K 下必然掉帧。我们的做法是骗过整个页面：把浏览器里的时钟、动画帧、定时器全部放慢八倍，页面以为世界很慢，截图就追得上了，最后按页面时间重采样成恒定的三十帧。这个手法在别的领域有很长的历史，FoundationDB 用确定性模拟测试分布式系统，格斗游戏用帧锁定做回放，思路都是把时间从物理世界里拿出来，交给控制者。代码视频是从源头就让画面只依赖时间，录屏是事后把时间接管过来，两条路通向同一个地方。

剪辑本身则是一份数据。十二个场景写在一个数组里，每个场景是片段名、时长上下限、一句标题、一行英文副标题，和一张放大卡片的位置。素材重录之后，时间线按实际长度自己重排。于是宣传片可以跟着产品一起重新生成：产品改版，重跑一遍录制和渲染，片子就是新的。走到这一步，宣传片其实成了产品的一次端到端测试，只是验收它的是人的眼睛。

片子的结构我也想得更清楚了。第一帧要能当封面。屏幕上的每个数字最好由系统算出，而不是手写在剧本里，否则产品一变，片子就会静默过期。结尾回到开头的状态，片子就能在展位上无缝循环，北交那部就是这样收尾的：觉之瞳闭眼，墨被钢笔吸回，落在片头那张空桌面上。我还导出了一个有码版，画面正中三分之一见方的区域打上高斯模糊，写上 @fish2lab，供转发用，内容看不清，作者看得清。

## AGENTS.md 是一级缓存

这些项目能在一个会话里做完、在另一个会话里接着做，是因为记忆不在对话里，而在仓库里。仓库里的记忆有层级，像一台计算机的存储体系。

AGENTS.md 是一级缓存，小，热，每次都被加载。BX 的这个文件只有 1588 字节，开头一句是「展位现场：27 寸 4K 显示器，循环播放一部无声短片，可能没有网络」。它只放 agent 看代码猜不到的东西：没有网络，所以只能 `file://`；屏上的价格只抄事实表，不编。docs 下的方案和施工文档是内存，写目的、取舍、分段、接口和验收命令，用到了才读。函数上方的注释是磁盘，git 历史是磁带库。agent 一开始只读一千多个字节，缺什么再按需调页，这就是渐进式披露。每一层只做一件事：告诉读者下一层在哪。一级缓存一旦想装下全部，命中率就会崩，AGENTS.md 也一样，写长了，agent 就分不清哪条是真要紧的。

那么一级缓存里该放什么？我的答案是伤疤。「所有脚本共用一个全局作用域，顶层名字带本段前缀」，背后是一次没有任何报错的静默覆盖。「勤提交，信息写 wip」，是因为 agent 被限流打断过，BX 里两个 salvage 分支就是从半路抢救回来的。「验收靠看抽帧和成片，不搭端到端测试」，是因为这里的产物是画面，覆盖率帮不上忙。本站的 AGENTS.md 第一段是 Next.js 官方放进来的，提醒 agent 这个版本和它训练数据里的不一样，先读仓库里的文档，这也是一道伤疤，只不过是整个社区的。一条规则如果说不出它来自哪次伤，就不该占用一级缓存。

还有一份文档是写给人的注意力的。帕秋莉讲座第五集的简报，结构是这样的：先写目的和主线，主线逐句列出，请我逐句认；然后是取舍，标题旁边写着「agent 已按目的选定；不同意再开口」；然后是要我回答的问题，只有一个，并且附了默认答案；然后是否决栏，初始写着「暂无」，那是我唯一需要动笔的地方；最后是一个折叠块，写给 agent，里面是材料分拣和要逐篇核对的引用。这个结构反转了 agent 默认的工作方式。agent 习惯提问，可在这件事里人的注意力才是最稀缺的资源，所以让 agent 先做决定，人只保留否决权。Apache 基金会管这个叫 lazy consensus，沉默即同意。我读它两分钟，agent 读它得到一份完整的施工输入。

## Agent 之间不聊天

hit-map 的第一个提交，除了数据契约，就是一张所有权表：哪些目录归数据与寻路，哪些归前端，哪个文件只有主会话能改。康威定律说，系统的结构会复刻组织的沟通结构。多 agent 协作把这条定律倒了过来：先画组织图，架构就跟着长出来。契约先定，两边同时开工。前端 agent 对着一个假的寻路器把界面写完，数据那边把真的做好，合并时换掉两行配置，谁也不需要读懂对方的代码。

每个 agent 待在自己的 worktree 里，那是一个真实的目录，各自抽帧、看图、提交，合并由主会话做。它们之间从不直接对话，只通过仓库交换信息：提交记录，分支名，施工文档里的状态栏，wip 开头的提交信息。生物学里有个词描述这种协作，叫 stigmergy，白蚁不互相下指令，只在环境里留下痕迹，后来的白蚁读痕迹接着干，最后垒出一座蚁丘。BX 第一轮有几个 agent 被限流停在半路，换成另一个模型 MiMo 接着做完，它没有读过任何一段前人的对话，读的是痕迹。状态在仓库里，换 agent、丢对话，代价都只是一次 git log。

第四段《雏祭》的第一版就停在 salvage/hina-v1 分支上。顶上转台里那个方块玩偶，是 agent 为了不依赖网络而手写的软件渲染器画出来的，左下角的署名是一个常量，不靠谁记得。

这套结构也延伸到了分发上。一份源码有好几个出口：hit-map 同时是网页、4K 成片、有码版，以及一张贴在教室门口的二维码。touhou 模板同时是可以一键开新集的模板仓库、一个在浏览器里实时渲染的演示页，还附带给 agent 的 llms.txt、给学术引用的 CITATION.cff。它的 README 里专门有一节写给 agent：先读哪个文件，调用一个角色的签名是什么，怎么不开浏览器就验收。那一节的读者不是人，但最后受益的是人，别人的 agent 读懂了，fork 出来的那一集就能用。

## 黑话是最高带宽的 prompt

哲学家波兰尼说，我们知道的多于我们能说出的。经济学家 Autor 用这句话解释过，为什么过去几十年自动化总在某些工作面前停下来：那些工作的知识是默会的，没法写成规则。agent 把这个局面翻了过来。你能说出来的，它基本都能做；它做不到的，常常是你说不出来的。瓶颈从「能不能实现」，挪到了「能不能命名」。我在[说「天赋」](/blog/talent-is-transfer)那篇里写过，学习几乎总意味着把知识显性化。和 agent 合作，是同一件事被推到了极致。

动效设计的黑话，就是一套被压缩过的默会知识。「让它顺一点」几乎没有信息量；「起步快，落地慢，用 easeOutExpo，不要回弹」，一句话就把手感说完了。下面四个词，每一个我都在这几个仓库里用过。

吸附，是把连续的量压到一组离散的位置上。它最有意思的地方在于跨了三个领域。界面里，hit-map 手机端的抽屉有三档，松手时按高度吸到最近的一档，分界取在 0.3，比两档的中点低，所以轻轻一拉就会展开，手指要用多大力气，是阈值决定的。几何里，程序生成的走廊被吸附到建筑外轮廓的主方向，同一排走廊共用一条线，T 形和十字接头于是干净了。时间里，传统动画「一拍二」，一个姿势停两帧；北交那部片子的第二段按 144 BPM 重排，二十四帧每秒下一拍恰好十帧，每个镜头都是十的倍数，切换落在拍点上。程序生成的东西看起来毛糙，多半差的就是这一步。**吸附是从「生成的」走到「设计过的」的那一步。**

咬合，是两个部件的边界严丝合缝。房间沿走廊切成条带，再按开间切开，布尔运算保证共边、铺满、不出外墙，每间房在走廊一侧开一个门洞，路线因此能指到「606 的门口」。片段之间的咬合是交接画面，相邻两段在接缝处画同一张静止画面，然后用脚本把每段的末帧和下一段的首帧逐像素比对。尺度上的咬合是 Powers of Ten 式的拉远，把接缝藏进画面里真实存在的框。形状上的咬合是「形状接形状」，眼皮线拉成隙间，魔药流成小溪。这个词好用，是因为它把一个审美判断变成了一个可以检查的问题：边界在哪，有没有缝。

过渡，有时长，有曲线，还有一个常被忘掉的属性：能不能被打断。地图的相机在你拖动时必须立刻跟手，所以用的是带阻尼的弹簧，随时改目标，速度始终连续；昼夜切换触发一次就播完，所以用六百毫秒的固定曲线。视频里没人会打断过渡，但它有另一个禁忌：弹簧在产品里是状态，下一帧取决于上一帧，在 f(t) 的世界里不被允许。于是角色身上的挂件，用的是写成时间闭式函数的弹簧，滞后的位移由过去半秒里锚点加速度的加权和直接算出。同一个物理直觉，在产品里和在视频里要写成两种数学。

贝塞尔曲线，是最值得学会「读」的那个。CSS 的 cubic-bezier 有四个数，起点和终点固定在 (0, 0) 和 (1, 1)，起点斜率是 y1 除以 x1，终点斜率是 (1 − y2) 除以 (1 − x2)。hit-map 界面用的 (0.22, 1, 0.36, 1)，起点斜率约 4.5，终点是零，时间才走了两成，进度已经快满了，剩下的时间都在慢慢停下来：手一松，界面立刻回应，然后安静。宣传片用的 (0.16, 1, 0.3, 1)，起点斜率 6.25，更猛，适合入场。路线一笔画出来用 (0.65, 0, 0.35, 1)，两端斜率都是零，起和停对称。四个数，就是一种性格。

这些词一旦有了名字，就可以变成 token。fish2lab 的 DESIGN.md 已经把颜色、字号阶梯和间距写成了 token，动效该是下一批：曲线、时长、吸附阈值都起好名字，agent 写界面和写片子时引用同一个名字。眼下 hit-map 的界面曲线和宣传片的曲线很像，却不是同一条，说明手感还停留在凭感觉的阶段。

## 人和 agent 各自留下的部分

回头看这几个项目，我和 agent 的分工是稳定的。我定目的，定画风，定取舍，说「不对」；它读资料，选范本，写代码，抽帧，写脚本检查自己。魔理沙的帽子在一个下午改了好几轮，每一轮的反馈由人给，改动由它做，再由人验收。agent 擅长按数字执行，所以我把审美翻译成数字；agent 擅长读文档，所以我把经验写成文档；agent 可以被换掉，所以状态放在仓库里。

数字媒体也在这里发生变化。一件作品同时是一个可以 fork 的模板，一种可以被引用的数据（deterministic 的视觉程序，给研究编码 agent 的视觉程序合成提供了干净的语料），一个别人的 agent 也读得懂的页面，乃至干脆开源代码或Skill。

## 回到那个文件夹

再回到开头那个七十美元的文件夹。仔细看，里面没有哪个文件算得上「作品」本身，那条 4K 的 mp4 只是它某一次的输出，删掉了，跑一遍命令就能再生成。作品是那套能把它重新生成出来的东西：一个只依赖时间的函数，一份写满数字的部件表，一张所有权表，一个一千多字节的入口文件，几个起好了名字的手感。

这篇文章绕了一大圈，讲的其实是同一次转移。生成变便宜之后，人的工作从「把东西做出来」，挪到了「让它可以被重新做出来」。约束、数字、名字、记忆、分工，这五样东西都不直接产生画面，可没有它们，agent 每一次产出的都只是一个样本，有了它们，产出的才是一个可以 fork、可以返修、可以交给下一个 agent 接着做的作品。

我常想起录音技术出现之前的音乐。那时候一首曲子只能以乐谱的形式流传，每一次演奏都是一次重新生成，演奏者不同，音色就不同，乐谱本身却一个音符都不会少。录音把音乐变成了文件，固定下来，也封死了。代码又把内容变回了乐谱，只不过这一次，演奏者是 agent，一个下午就能把同一份谱子演奏几十遍。一位画师的风格可以写成一份部件表，一个人的工程经验可以写成一份 AGENTS.md，交给任何人的 agent 去演奏。

演奏者换了，耳朵还得是人的。魔理沙的帽子应该罩住头顶，而不是浮在头上，这个判断不在任何一份部件表里，是看合照的人给出来的，那一眼背后是看过的无数同人画和动画。agent 可以在一个下午演奏一千遍，但判断哪一遍对，依然要靠一双被一千首曲子磨过的耳朵。

凡操千曲而后晓声，观千剑而后识器。
